## Key Concepts

### 1. What Django Is
Django is a **web framework** -- it handles the plumbing of web applications (routing URLs, managing databases, handling HTTP requests) so you can focus on your application's logic. It follows the **MVT** (Model-View-Template) pattern:

- **Model**: Defines your data structure (like a class from Day 1, but mapped to a database)
- **View**: The logic that processes requests and returns responses
- **Template**: The HTML that gets rendered and sent to the browser

### 2. Project Structure
```
Day_03_PCC_Django/
├── manage.py              # Command-line utility to run the project
└── ll_project/            # The project package
    ├── __init__.py        # Makes this directory a Python package
    ├── settings.py        # All project configuration
    ├── urls.py            # URL routing -- maps URLs to views
    ├── asgi.py            # Entry point for async web servers
    └── wsgi.py            # Entry point for traditional web servers
```

### 3. Key Files Explained

**`manage.py`** -- The command center. You use it for everything:
```bash
python manage.py runserver     # Start the development server
python manage.py makemigrations  # Create database migration files
python manage.py migrate       # Apply migrations to the database
python manage.py createsuperuser  # Create an admin account
```

**`settings.py`** -- Project configuration. Notable settings:
- `SECRET_KEY`: Used for security (never share this in production)
- `DEBUG = True`: Shows detailed errors (turn off in production)
- `INSTALLED_APPS`: List of active Django apps
- `DATABASES`: Database configuration (SQLite by default)

**`urls.py`** -- URL routing. Maps URL paths to view functions:
```python
urlpatterns = [
    path("admin/", admin.site.urls),  # Built-in admin panel
]
```

**`__init__.py`** -- An empty file that tells Python "this directory is a package." This is the same concept as importing modules from Day 1 (`from car import Car`), but at the directory level.

### 4. Connection to Python Concepts You Already Know
- `settings.py` uses `pathlib.Path` (Day 2): `BASE_DIR = Path(__file__).resolve().parent.parent`
- The project structure uses **modules and packages** (Day 1 imports)
- `manage.py` uses `if __name__ == "__main__"` -- this means the code only runs when the file is executed directly, not when imported

## Common Pitfalls

- **Forgetting to activate a virtual environment**: Django should be installed in a virtual environment, not system-wide. If `import django` fails, check your venv.
- **`SECRET_KEY` in version control**: The auto-generated key is fine for learning, but in a real project, move it to an environment variable.
- **Confusing "project" vs "app"**: A Django **project** is the overall site. An **app** is a specific feature (e.g., blog, user accounts). One project can have many apps.
